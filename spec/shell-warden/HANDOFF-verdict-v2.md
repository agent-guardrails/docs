# HANDOFF - Verdict v2 implementation

References: [docs issue 33](https://github.com/agent-guardrails/docs/issues/33), [primary issue 13](https://github.com/agent-guardrails/opencode-shell-warden-hook/issues/13), [design](https://github.com/agent-guardrails/docs/blob/main/design/shell-warden-verdict-v2.md), current [ADR-0023](https://github.com/agent-guardrails/docs/blob/main/adr/0023-shell-warden-verdict-v2-only.md), superseded historical [ADR-0020](https://github.com/agent-guardrails/docs/blob/main/adr/0020-versioned-shell-warden-verdict-envelope.md) and [ADR-0022](https://github.com/agent-guardrails/docs/blob/main/adr/0022-post-schema-shell-warden-verdict-validation.md), [normative contract](https://github.com/agent-guardrails/docs/blob/main/spec/shell-warden/02-letter-verdict.md), and [`verdict v2 schema`](https://github.com/agent-guardrails/docs/blob/main/schemas/shell-warden.verdict.v2.schema.json).

## Rust checker

1. Introduce v2 envelope DTOs and one explicit v2 writer. Keep v1 letter parsing and the released v1 schema immutable.
2. Map complete to static with argv, opaque to opaque with raw, and invalid to invalid with raw. Preserve invalid-over-opaque-over-complete precedence and `deny > ask > allow` reduction.
3. Emit v2 for every outcome. Do not emit v1, negotiate protocol, probe consumer capability, or select output version from evidence.
4. Validate and serialize only v2 output. Echo the letter invocation ID. Enforce positional contiguous indexes equal to array positions in letter and verdict, schema combinations, command-to-aggregate consistency, deny message, optional aggregate allow/ask message, the matching-command-verdict UTF-8-byte-order rule-ID choice, 16 KiB/depth-8 facts bounds, 64 KiB output bound, recognized full/truncated diagnostics evidence/reason coherence, full static/argv/allow emitted-allow proof, and full-diagnostics emitted-vote coherence.
5. Consume only shared-manifest v2 vectors with the `checker-producer` role for semantic output construction or the `checker-serialization` role for schema/wire serialization. A vector MAY have multiple roles. Do not consume `hook-consumer`-only vectors. Add conformance tests for every allowed and rejected combination, invalid default bare ask, invalid emitted ask with deterministic `ruleId`, invalid ordinary-rule deny, aggregate cases, raw verdict/facts/depth bounds, both diagnostics shapes, deterministic complete, opaque, and invalid truncation anchors, canonical rejected construction, unknown `match` value, foreign invocation, default ask rule-ID omission, mixed reasons, Unicode UTF-8 rule-ID ordering, and v2-only emission. Invalid evidence establishes an ask floor, never allows, and may match ordinary ask or deny rules against retained typed evidence or raw text. Flat v1 rejection and other consumer-only anomaly vectors are hook requirements, not Rust checker requirements.

## TypeScript hook

1. Define only the exact v2 response type. Enforce the 64 KiB cap before JSON parsing. The decoded root must carry exact v2 protocol; flat v1, absent protocol, and every other protocol are anomalies.
2. Use strict closed v2 validation, then apply semantic invariants against the expected invocation ID and positional indexes. Failed validation MUST use `onCheckerError` without fallback. Validate invocation echo, positional contiguous indexes equal to array positions in letter and verdict, recognized full/truncated diagnostics evidence/reason coherence, full static/argv/allow emitted-allow proof, rule-ID selection and default-ask omission, classification and match combinations, required deny message, optional aggregate allow/ask message, and aggregate consistency.
3. Return only the validated nested v2 result to the existing tighten-only application path. Flat v1, unknown or malformed output, and semantic failures MUST use `onCheckerError`. Never synthesize allow.
4. Consume all and only shared-manifest v2 `hook-consumer` vectors and rejected-response anomaly vectors. A vector MAY have multiple roles. Test exact v2 handling, flat v1 rejection, absent or malformed protocol, failed v2 without fallback, the 64 KiB pre-parse cap, positional contiguous command-index coverage, raw verdict/facts/depth caps, invalid default bare ask, invalid emitted ask with deterministic `ruleId`, invalid ordinary-rule deny, deterministic complete, opaque, and invalid truncation anchors, canonical rejected construction, unknown `match` value, foreign invocation, default ask rule-ID omission, mixed reasons, Unicode UTF-8 rule-ID ordering, both diagnostics shapes, and aggregate mismatch. These are implementation requirements; this docs repository supplies no execution evidence.

## Release order

Publish and deploy the hook and checker together as one coordinated v2-only pair. No dual-read, compatibility shim, old-checker rollout, or rollback that restores v1 is supported. Do not report migration complete until the requirements in [11 §11.5](https://github.com/agent-guardrails/docs/blob/main/spec/shell-warden/11-roadmap.md#115-verdict-v2-rollout-and-release-completion) are met.
