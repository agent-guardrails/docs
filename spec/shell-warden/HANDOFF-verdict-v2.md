# HANDOFF - Verdict v2 implementation

References: [docs issue 31](https://github.com/agent-guardrails/docs/issues/31), [primary issue 13](https://github.com/agent-guardrails/opencode-shell-warden-hook/issues/13), [design](https://github.com/agent-guardrails/docs/blob/main/design/shell-warden-verdict-v2.md), current [ADR-0022](https://github.com/agent-guardrails/docs/blob/main/adr/0022-post-schema-shell-warden-verdict-validation.md), superseded historical [ADR-0020](https://github.com/agent-guardrails/docs/blob/main/adr/0020-versioned-shell-warden-verdict-envelope.md), [normative contract](https://github.com/agent-guardrails/docs/blob/main/spec/shell-warden/02-letter-verdict.md), and [`verdict v2 schema`](https://github.com/agent-guardrails/docs/blob/main/schemas/shell-warden.verdict.v2.schema.json).

## Rust checker

1. Introduce v2 envelope DTOs and one explicit v2 writer. Keep v1 letter parsing and the released v1 schema immutable.
2. Map complete to static with argv, opaque to opaque with raw, and invalid to invalid with raw. Preserve invalid-over-opaque-over-complete precedence and `deny > ask > allow` reduction.
3. Emit v2 for every outcome. Do not emit v1, negotiate protocol, probe consumer capability, or select output version from evidence.
4. Validate and serialize only v2 output. Echo the letter invocation ID. Enforce positional contiguous indexes equal to array positions in letter and verdict, schema combinations, command-to-aggregate consistency, deny message, optional aggregate allow/ask message, the matching-command-verdict UTF-8-byte-order rule-ID choice, 16 KiB/depth-8 facts bounds, 64 KiB output bound, recognized full/truncated diagnostics evidence/reason coherence, full static/argv/allow emitted-allow proof, and full-diagnostics emitted-vote coherence.
5. Consume only shared-manifest v2 vectors with the `checker-producer` role for semantic output construction or the `checker-serialization` role for schema/wire serialization. A vector MAY have multiple roles. Do not consume `hook-consumer` vectors. Add conformance tests for every allowed and rejected combination, invalid default bare ask, invalid emitted ask with deterministic `ruleId`, invalid ordinary-rule deny, aggregate cases, raw verdict/facts/depth bounds, both diagnostics shapes, deterministic complete, opaque, and invalid truncation anchors, canonical rejected construction, unknown `match` value, foreign invocation, default ask rule-ID omission, mixed reasons, Unicode UTF-8 rule-ID ordering, and v2-only emission. Invalid evidence establishes an ask floor, never allows, and may match ordinary ask or deny rules against retained typed evidence or raw text. Malformed or partial reserved-key v1 diagnostics are `hook-consumer` only, not Rust checker requirements.

## TypeScript hook

1. Define exact v1 and v2 response types. Enforce the 64 KiB cap before JSON parsing. Discriminate from decoded root: absent protocol selects exact v1; exact v2 protocol selects exact v2; every other protocol is an anomaly.
2. Use strict closed validation, then apply semantic invariants to both selected versions against the expected invocation ID and positional indexes. Failed v2 validation MUST NOT fall back to v1. Validate invocation echo, positional contiguous indexes equal to array positions in letter and verdict, recognized full/truncated diagnostics evidence/reason coherence, reserved-key v1 facts recognition, full static/argv/allow emitted-allow proof, rule-ID selection and default-ask omission, classification and match combinations, required deny message, optional aggregate allow/ask message, and aggregate consistency. Exact-valid v1 opaque/argv/allow and every other impossible v1 tuple MUST use `onCheckerError`.
3. Return the validated nested v2 result, or validated v1 result, to the existing tighten-only application path. Unknown or malformed output MUST use `onCheckerError`. Never synthesize allow.
4. Add revision-pinned shell-warden v0.4.0 `04cfe594b433d05343044bb848891d7942a4b87c` and hook v0.2.1 `7090301963bed3fbe9d2a3f0babf413d521f75f4` harness tests with revision provenance: v0.4.0 exact-valid-v1 preservation and v0.2.1 v2-envelope rejection through `onCheckerError`. Consume all and only shared-manifest `hook-consumer` vectors across v1 and v2. A vector MAY have multiple roles. All malformed or partial reserved-key v1 vectors are `hook-consumer` only and are hook-owned. Also test exact v2 handling, malformed protocol, failed v2 without fallback, the 64 KiB pre-parse cap, positional contiguous command-index coverage, raw verdict/facts/depth caps, invalid default bare ask, invalid emitted ask with deterministic `ruleId`, invalid ordinary-rule deny, deterministic complete, opaque, and invalid truncation anchors, canonical rejected construction, unknown `match` value, foreign invocation, default ask rule-ID omission, mixed reasons, Unicode UTF-8 rule-ID ordering, both diagnostics shapes, aggregate mismatch, and all four rollout states. These are implementation requirements; this docs repository supplies no execution evidence.

## Release order

Publish compatible hook and checker releases together as one coordinated pair. Deploy the dual-read hook first, then deploy the v2-only checker. Roll back the checker first. Do not report migration complete until the requirements in [11 §11.5](https://github.com/agent-guardrails/docs/blob/main/spec/shell-warden/11-roadmap.md#115-verdict-v2-rollout-and-release-completion) are met.
